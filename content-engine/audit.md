# Audit technique initial — 2026-11-09

Dépôt npm workspaces : landing `apps/landing-page`, Next.js 16.3.8, React 19 et TypeScript ; application SaaS séparée. `src/lib/blog.ts` est le registre typé unique ; `/blog/[slug]` construit les routes statiques, metadata et `BlogPosting` ; `src/lib/site.ts` définit le domaine canonique. `sitemap.ts` et `robots.ts` utilisent les conventions Next.js. `BlogPostTemplate` et `blog-inline-text` rendent sections et liens ; les images sont dans `public/images/blog`. `public-content.ts` contient les pages liées. Les tests `e2e/seo-public-pages.spec.ts` contrôlent le rendu et les liens. Lint et build : `npm run lint:landing`, `npm run build:landing`. CI existante `.github/workflows/quality.yml`. Le dépôt prévoit la livraison par PR et validation propriétaire avant merge et production ; aucun environnement de préproduction autonome n'est documenté.

Décision : outil local déterministe lisant le registre existant, aucun CMS ni service externe. Les briefs restent hors du registre, donc invisibles sur le site. Le contrôle statique complète les tests de rendu et n'évalue pas la véracité. Un article préparé dans le registre serait publiable dès le prochain déploiement : validation humaine obligatoire. Ne pas modifier les chemins publics. Les rôles sont séquentiels. Le kit fourni sert de référence ; ses prompts sont à adapter aux règles de ce dépôt.
